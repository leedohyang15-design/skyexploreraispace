## ① `scripts/golden/SHOW_perseids.py` — 오늘 밤이 극대 (약 2분 12초)

**시의성이 있는 유일한 항목.** 내일이면 평범한 쇼가 됩니다.

| 볼 것 | 왜 |
|---|---|
| [ ] 유성이 **한 점에서 방사**되나 | `setReferential(RaDec)` 가 먹었는지. 이게 안 먹으면 아무 방향에서나 튀어나온다 |
| [ ] 그 점이 **페르세우스자리 위**인가 | 복사점 좌표(적경 47 / 적위 58)가 맞는지 |
| [ ] **ZHR 900 이 성긴가 / 적당한가** | 실제값 100 은 돔에서 안 보여 900 으로 올렸다. 성기면 1500 으로 올린다 |
| [ ] 극대의 **2400 이 과한가** | 과하면 1800 으로. "비 오듯" 이 목표지 "화면이 하얘짐"이 아니다 |
| [ ] 북동 하늘에 페르세우스가 **떠 있나** | `H=135`(북동) + 틸트 22 로 잡았다. 지평선 아래면 시각/방위를 다시 계산해야 한다 |

⚠️ 복사점이 화면 밖이면 **유성은 나오는데 어디서 오는지 안 보인다** — 이 쇼의 핵심이 죽습니다.
그 경우 `H_NORTHEAST` / `TILT` 값을 알려주시면 조정합니다.

그러면 **"규칙을 넣었더니 결과가 이렇게 달라졌다"** 는 비교 자료가 통째로 생깁니다(시연에서도 좋은 소재).

# 2차 — 짧은 예제 7개 (배치 1회 재생, 약 4분 10초)

`scripts/demo/BATCH_g_series.py` **한 파일만** 불러오면 7개가 순서대로 돕니다.
절 사이에 2초 암전 + 로그 마커가 있어 어디서 끊겼는지 바로 보입니다.

⚠️ 이 배치는 **자동 생성물**입니다. 고칠 게 있으면 원본 `g*.py` 를 고치고
`python3 tools/make_batch.py` 로 재생성하세요.

| # | 파일 | 판정 포인트 |
|---|---|---|
| 1 | `g1_mars_closeup` | [ ] 줌이 폭발하지 않고 화성 표면이 보이나 |
| 2 | `g7_mars_flight` | [ ] 도착 폴링이 먹어 카메라가 안 날아가나 |
| 3 | `g2_catseye_travel` | [ ] **NEBULA 패널 = GoTo 여행이 되나** |
| 4 | `g3_rosette_show` | [ ] **NGC 패널 = 제자리 ON + ScaleUp 만 되나** |
| 5 | `g4_constellation_slider` | [ ] 선/그림/라벨이 한 번에 부드럽게 페이드되나 |
| 6 | `g5_spaceship_approach` | [ ] Insert2D 애니가 영상처럼 움직이나 |
| 7 | `g8_world_sky_tour` | [ ] 관측지가 이름으로 옮겨지고 하늘이 실제로 바뀌나 |

**3↔4 가 이 배치의 핵심입니다.** 딥스카이는 *어느 패널 소속이냐*로 되는 게 갈린다는 게
우리 지식의 큰 축인데(같은 NGC 번호라도 소속이 다르면 여행 가부가 갈림), 아직 미확인입니다.
둘을 나란히 보면 한 번에 판정됩니다 — **3 은 날아가고 4 는 제자리면 규칙이 맞습니다.**

**1↔2 도 짝입니다.** 같은 화성인데 하나는 도킹 후 줌, 하나는 비행 도착입니다.

## 끝나고

번호별로 O/X 만 주시면 됩니다. 예:

```
1 O / 2 O / 3 O / 4 제자리는 되는데 ScaleUp 이 안 보임 / 5 O / 6 O / 7 O
```

X 가 나온 것만 원본을 고치고 배치를 재생성하겠습니다.
