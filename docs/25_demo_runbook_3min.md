## ⏱ 3분 타임라인

| 시각 | 화면 | 말할 것 | 조작 |
|---|---|---|---|
| **0:00–0:25** | 빈 돔 (또는 로고) | "지금 이 돔에서 쇼 하나 새로 만들려면 며칠이 걸립니다. 스크립트 짜고, 돌려보고, 각도 틀리면 다시 짜고." | — |
| **0:25–0:35** | 노트북 화면 (앱) | "그걸 이렇게 해보겠습니다." | 프롬프트 입력창에 아래 문장 타이핑 |
| **0:35–1:05** | 생성 중 | ⚠️ **침묵 금지 구간.** "지금 하는 일이 두 가지입니다. 하나는 장면을 짜는 것, 하나는 이 돔의 규칙을 지키는 것 — 관객이 목 안 꺾게 각도를 30도로 잡고, 카메라 자세 바꾸는 구간은 암전으로 가리고." | 생성 대기 (20~40초) |
| **1:05–1:20** | 생성된 코드 | "사람이 손댄 곳 없습니다. 규칙 검사도 자동으로 걸려 있어서, 어기면 스스로 고쳐서 다시 냅니다." | 코드 스크롤 한 번 |
| **1:20–2:40** | **돔 재생** | (재생 초반 10초는 말하지 말 것 — 관객이 화면을 보게 둔다) 이후 한두 마디만. | Studio 로 옮겨 실행 |
| **2:40–3:00** | 돔 (여운) | "말로 하면 돔에서 도는 것까지, 방금 3분입니다. 기획자가 직접 만들 수 있게 되는 게 핵심입니다." | — |

### 라이브로 칠 문장 (검증된 것 그대로)

```
청주에서 지구 자전으로 별이 도는 걸 보여줘
```

이 프롬프트를 쓰는 이유:
- 결과가 **약 45초** — 3분 안에 들어간다
- 변화가 **한눈에 보인다**(별이 북극성 중심으로 돈다). 미묘한 효과는 시연에 부적합
- 이미 같은 프롬프트로 생성한 결과물이 `demo1_diurnal.py` 로 남아 있어 **폴백이 자연스럽다**

## 🛟 폴백 사다리

시연에서 제일 위험한 건 라이브 생성이다. **3단으로 준비하고, 20초 이상 막히면 바로 다음 칸으로 넘어간다.**

| 상황 | 대응 | 관객에게 할 말 |
|---|---|---|
| 생성이 40초 넘게 안 끝남 | `demo1_diurnal.py` 재생 | "같은 문장으로 어제 만들어 둔 게 있습니다. 이겁니다." |
| API 하루 한도 초과 (429) | 같은 카드 | (위와 동일 — 굳이 한도 얘기를 꺼내지 말 것) |
| 생성은 됐는데 돔에서 이상함 | `demo2_saturn_rings.py` 재생 | "각도가 안 맞네요. 다시 시키면 되는데, 시간상 만들어 둔 걸로 보시죠." |
| 돔/Studio 자체가 안 됨 | 노트북으로 코드만 보여주고 스샷 | 제안서의 스샷 페이지로 전환 |

⚠️ **폴백을 숨기지 마라.** "미리 만들어 둔 것"이라고 말해도 손해가 아니다 —
*만들어 두면 관에 쌓인다*가 오히려 세일즈 포인트다. 숨기려다 들키는 게 훨씬 나쁘다.

## 💬 예상 질문과 답

**"AI가 틀린 걸 만들면요?"**
> 두 겹으로 막습니다. 하나는 규칙 검사 — 생성된 코드를 자동으로 검사해서 위반이 있으면 고쳐서 다시 냅니다.
> 다른 하나는 사람 확인 — 돔에서 한 번 보고 통과시키는 절차가 있고, 어느 쇼가 확인됐는지 기록으로 남깁니다.
> (검증 원장을 보여줘도 좋다. **"확인 0 / 부분확인 3 / 미확인 12" 를 그대로 보여주는 게 신뢰를 얻는다** —
>  다 검증됐다고 말하는 쪽이 오히려 의심을 산다.)

**"소리는요?"**
> 스크립트로는 못 냅니다. 이 빌드에서 파이썬 오디오·영상 재생은 별도 호스트 소관이라 막혀 있고,
> 확인까지 마쳤습니다. 음향은 기존처럼 오퍼레이터가 입힙니다.

**"기존 SPC 쇼는요?"**
> 변환기가 있습니다. SPC 녹화를 파이썬으로 바꿔서 이 파이프라인에 태웁니다.

**"우리 관 장비에서 돌아가나요?"**
> 스크립트는 Studio 창에서 그대로 돕니다. 다만 비행 카메라 조작이나 날씨 효과처럼
> 오퍼레이터/하드웨어 소관인 기능은 스크립트로 제어가 안 됩니다. 그 경계는 문서로 정리해 뒀습니다.

## ❌ 시연에서 하지 말 것

- **미확인 쇼를 라이브로 틀지 말 것.** [원장](24_verification_ledger.md)에서 확인/부분확인만 쓴다.
- **긴 쇼 금지.** 3분 안에 도입·생성·재생이 다 들어가야 한다. 재생은 **90초 이하**.
- **미묘한 효과 금지.** 무지개·고리 밝기·구름 양처럼 "차이를 설명해야 보이는" 것은 시연에 부적합하다.
  일주운동·위성 공전·고리 개방처럼 **말 안 해도 보이는 것**만.
- **생성 대기 중 침묵 금지.** 30초 침묵은 실패처럼 보인다. 대기 시간에 할 말을 미리 정해 둘 것.
- **한도 얘기 먼저 꺼내지 말 것.** 물으면 답하되, 먼저 말하면 제약처럼 들린다.
