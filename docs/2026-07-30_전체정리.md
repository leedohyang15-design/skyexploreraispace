1. **"死"로 묻었어도 접근 방식을 바꾸면 살아난다** — 수동↔프리셋, 접근↔제자리 ON, NgcType↔NebulaType.

## C. 카메라 완전 정리 (Camera 36개 전수)

### 평상시 이 6개면 충분
| 하고 싶은 것 | 명령 |
|---|---|
| 방위(좌우) | `setOrientationH(H)` — 지상 조준 **H = 180 − 천체방위** |
| 고도(위아래) | `setTargetHeight(t)` — **관람 표준 30** |
| 회전(롤) | `setOrientationHPR(Vec(H,P,R+360))` — 성운·성단 스핀 |
| 위치(대상 주위) | `setPositionLBR(Vec(L,B,R), Anim, -1)` |
| 줌(거리) | `setPositionR(p0/배율, Anim, -1)` |
| B만 변경(R 보존) | `setPositionB(값, Anim, -1)` |

**+ 보조 2**: `setOrientationSmoothXYZR(Vec4(0,0,0,0), Anim, port)`(프레임 전환 정렬) · `setZoomFov`(우주 광학줌)
**+ 특수 2**: `setTargetAzimuth`(타겟 기준 상대 회전) · `setTraceMode(True)`(궤적 — 과하게 남으니 짧게)

### 비슷한 명령들의 진짜 차이
- **대원칙: `track` 인자 유무** — 없으면 현재 프레임 속성 세터 / 있으면 좌표계 지정 가능(-1=현재)
- `setOrientationP` vs `setTargetHeight`: 결과 같음. **Target 계통이 HUD·운영표준의 기준** → Target 을 씀
- `setOrientationR` vs `setOrientationH`: **Roll(시선축) vs Heading(수직축)**. 지상 Target30 에선 비슷해 보이나 **천정·성운 프레임에선 완전히 다름**
- `setTargetAzimuth` vs `setOrientationH`: **상대 회전 vs 절대 방위**(조준 공식 성립)
- `XYZ`(롤X, trackX) < `XYZR`(롤O, trackO) < **`SmoothXYZR`**(+부드러운 보간) → 프레임 정렬은 항상 Smooth
- `setOrientationHPR`(track **없음**) vs `HPRD`(track **있음**) — D 는 무의미하나 **좌표계 지정이 필요하면 HPRD 가 유일**
- `setPositionL/B`(성분만, **R 보존**) vs `setPositionLBR`(셋 다 → **R 폭발 위험**)
- `setPositionXYZ`(직교, 단위 불명) vs `setPositionLBR`(구면, **R=거리라 배율 계산 직관적**)

### 실측 무변화 / 하드웨어
- 🛑 무변화: `setFocusDegree` · `setOrientationD` · `setActiveTarget` · HPRD 의 D
- ⚙️ 돔 하드웨어(건드리지 말 것): `setEyeDistance` · `setStereoPosition/Ratio` · `setActiveTrackStereo` · `setDomeMeanPixelRatio` · `setResolutionRatioStrength`

### 5번 `setOrientationSmoothXYZR` 의 Vec4 정체
**(X,Y,Z)=바라볼 방향벡터 + R=Roll 각도(도)** — 쿼터니언 아님(HPR 로그로 확정).
프레임 전환 정렬은 `(0,0,0,0)`, 일반 회전은 6번 HPR 이 직관적.

## D. 이동/여행 완전 정리

### 비행 명령 비교 (화성, 동일 조건 실측)
| | **GoTo** ⭐권장 | **StraightGoTo** | **FadeTo** | **ConnectTo** |
|---|---|---|---|---|
| 방식 | 비행 | 비행 | 페이드 순간이동 | 프레임만 전환 |
| 시작 | **지상 '이륙'**(R 0→2.14) | 즉시 프레임 점프 | — | — |
| 회전 | **이동과 섞임**(자연스러움) | **분리**(앞 10초 화면만 돎) | — | 내부 Look-at 슬루 |
| 소요 | **~20초** | ~24초 | ~5초 | ~4초 |
| 도착 | **R=4.01**, B=89.99 | R=5.00, B=90.00 | 행성 R=5 / 딥스카이 R=0 | 실제 거리 유지 |

**→ 여행 연출은 GoTo. 빠른 전환은 FadeTo. 흔들림 없이 프레임만 잡으려면 ConnectTo.**
✅ 옛 노트 *"암석행성 GoTo 도킹 {L, 89.999, R=4}"* 가 실측(4.01/89.99)과 정확히 일치 = 검증됨.

### 딥스카이 접근 3단 우선순위 — **카테고리가 능력을 결정**
1. **NEBULA 패널 27개**(`NebulaType`) → **GoTo/FadeTo 여행 가능**
   (말머리·M1·M16·M42·**NGC2346**·**NGC2392**·**NGC6543**·**NGC7293** 등)
2. **그 외 메시에·은하·성단**(M31·M13·M45) → **GoTo 없음** → `ConnectTo` + 절대타겟 줌
3. **NGC 패널**(`NgcType`, 장미 NGC2237) → **이동 액션 전무** → 제자리 ON + `LookAt` + `ScaleUp` 반복

⚠️ **같은 NGC 번호라도 패널 소속이 능력을 가른다** — NGC2346 은 NEBULA 소속(여행 O, NgcType 으론 안 찾아짐).

### 관측지 이동 (신규)
```python
DataManager.database().data(Data.Type.CityType, "Paris").action(Action.Type.GoTo).trigger()
```
- 실측: 청주(36.64,127.49,200m) → **서울(37.599,126.978,100m)**, 1~2초, **지상 시점 유지**
- 타입: `CityType`(Seoul/Paris/New York/London/Tokyo) · `MountainType`(Mont blanc/Everest) · `VolcanoType`(Etna)
- 좌표 하드코딩 불필요, **고도까지 자동**

| 함정 | 증상 | 해결 |
|---|---|---|

| **줌 원칙 위반** | 줌이 "하다가 마는" 끊김 | ① 절대타겟(p0 **한 번만** 읽기) ② 선형 Anim + `sleep < anim` 겹치기 |
| **`positionLBR` 되써넣기** | R 16,981km → 99.63Gm 폭발 | R 은 `setPositionR`, B 는 `setPositionB` 로만 |
| **B 조정** | 행성이 천정으로 올라가 목 꺾임 | **B 는 도킹 기본값 유지**(암석 90/가스 20). 프레이밍은 Target 으로만 |
| **성단 scale 읽는 순서** | `scale=0.0` → ×700=0 → 확대 안 됨 | `orig = gc.scale` 을 **FadeTo 전(지상)** 에서 읽기 |
| **액션 3개만 스캔** | "NGC 死" 오판 | `.action()` None 판정은 **Action.Type 전체 스캔** 후에 |
| **ParamLut 프레임 대기 누락** | `enabled` 가 False 로 남음 | `setEnabled(True)` 후 **`sleep(1.5)`** |
